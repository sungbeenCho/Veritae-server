# 가짜정보(허위정보) 판별 기능 — 설계

- **작성일**: 2026-09-29
- **관련 메모리**: `project_veritae_misinformation_detection`, `feedback_no_llm`, `project_veritae_fraud_model_reinvestigation`, `feedback_never_decide_design_alone`
- **표기 규칙**: 각 결정 옆에 **[확정]**을 붙인다. 초안 작성 중 Claude가 새로 제안해 사용자 결정이 필요했던 항목(A~F)은 §13에 정리했고, 전부 확정됐다.

## 1. 목적과 범위

이미지·음성·영상에서 뽑은 문장 중 **한국어 위키백과 내용과 어긋나는 주장**을 찾아, 그 이유와 위키 근거를 함께 보여준다.

- **스코프 = 일반 주장의 사실 검증** [확정]. "이건 금감원 공식 공지다" 같은 사칭성 주장 검증은 제외한다. 대조할 공식 화이트리스트가 없고(경찰청 신고번호, KISA 피싱 URL은 블랙리스트뿐), 목적도 사기감지와 겹치기 때문이다.
- **근거 제시형 보조 도구** [확정]. 판정이 틀릴 수 있다는 전제로, 판정에는 항상 근거 원문과 링크를 함께 보여주고 최종 판단은 사용자가 하게 한다.
- **거짓으로 판정된 문장만 보여준다** [확정]. 참이나 판단불가로 나온 문장은 응답에 넣지 않는다.
- **모든 문장을 검사한다** [확정]. 일부만 검사하는 상한은 두지 않는다.
- **비동기로 빼지 않는다** [확정]. 이미지·음성은 기존 동기 응답에, 영상은 기존 job 결과에 함께 담는다.

**범위 밖**: 사기감지 모델(Lilju) 교체, AntiDeepfake의 GPU 전환, 검증 가치가 있는 문장만 고르는 필터(check-worthiness), 사칭성 주장 검증.

## 2. 왜 이 구조인가 (2026-09-29 실측 요약)

| 확인한 것 | 결과 |
|---|---|
| NLI 분류 모델 4종(36건 세트) | Huffon klue-roberta-base 21/36(인용+부정 0/12, 거짓을 사실로 판정 10건), ys7yoo large 31/36, mDeBERTa 30/36, xlm-roberta-large 32/36 |
| 로컬 LLM qwen3.5:4b | 36건 36/36, 처음 보는 어려운 16건 16/16(mDeBERTa는 13/16, 위험 오답 2건) |
| 위키 검색까지 포함한 전체 흐름(20건) | 16/20, 위험 오답 0. 틀린 4건은 모두 판단불가로 물러남(검색 실패 2, 조각 선택 1, 보수적 추론 1) |
| 공개 위키 검색 API | 몇 번 호출만으로 429(요청 과다) → 동기 응답에 쓸 수 없음 |
| 속도(노트북 CPU) | 판정 한 번에 25~40초, 대부분은 근거를 읽는 시간(prefill). 모델 로드 13초. 데스크탑 GPU 수치는 미측정 |
| 두 단계 판정(라벨만 먼저) | 16%만 빨라지고 판정 4/20이 바뀜(참 문장을 거짓으로 판정 1건) → 기각 |

LLM은 비용 문제로 금지돼 있었으나, 데스크탑에서 로컬로 돌리면 비용이 없어 사용하기로 했다 [확정].

## 3. 전체 흐름

```
[분석 요청] ─┬─ AI 판독(SPAI / AntiDeepfake / dfdc) ────────────────────────┐
             └─ 텍스트 추출+사기감지(scam_infer.py) ── 문장 목록 ── 가짜정보 판정(misinfo_infer.py) ─┤
                                                                                      ↓
                                               {ai_detection, scam_detection, misinformation_detection}
```

- 가짜정보 판정은 사기감지가 **이미 뽑아 둔 문장**을 그대로 받아 쓴다 [확정: 문장분리 재사용]. 텍스트 추출을 두 번 하지 않는다.
- 그래서 가짜정보 판정은 사기감지가 끝난 뒤에 시작한다. AI 판독과는 계속 병렬이다.

문장 하나에 대해 하는 일:
1. Kiwi로 형태소를 분석해 핵심어를 뽑고, 위키 인덱스(SQLite FTS5)에서 BM25로 후보 조각 약 50개를 찾는다.
2. 후보를 e5-small 임베딩으로 문장과 비교해 가장 가까운 5개를 고른다.
3. 문장과 조각 5개를 LLM에 넣어 `지지 / 반박 / 판단불가`와 이유 한 문장을 받는다.
4. `반박`인 문장만 결과에 넣는다.

## 4. 위키 인덱스

- **데이터** [확정]: 매달 나오는 공식 XML 덤프 `kowiki-latest-pages-articles.xml.bz2`(약 1.4GB, 문서 약 77만 개). CirrusSearch 평문 덤프는 2025-12-29 이후 갱신이 멈춰서 쓰지 않는다.
- **변환** [확정]: mwparserfromhell(MIT)로 평문을 만든다. ref, gallery, math 태그와 이미지 링크, 표를 먼저 제거한다(5,000문서 샘플에서 1.6%에 이미지 설명문과 표 찌꺼기가 남았던 문제). 문장 단위로 이어 붙여 약 200자 조각을 만든다.
- **검색** [확정]: SQLite FTS5 파일 하나를 디스크에 둔다. 조각 본문을 Kiwi(Apache-2.0)로 형태소 분석한 결과를 색인하고, 조회도 같은 방식으로 분석한 핵심어로 한다. RAM에 인덱스 전체를 올리지 않는다.
- **구축** [확정: 데스크탑에서 한 번]: `scripts/build_wiki_index.py`가 덤프 → 변환 → 조각 → 색인까지 한 번에 한다. 노트북(순수 파이썬 파서)에서는 변환에만 7시간 이상 걸리는 속도였다. 데스크탑은 C 확장 파서를 쓸 수 있어 더 빠를 것으로 예상하지만 미측정.
- **인덱스 파일 안에 덤프 날짜를 저장**하고, 응답의 `wikiSnapshot`으로 내보낸다.
- **갱신 주기 [확정]**: 자동 갱신 없음. 사용자가 원할 때 `build_wiki_index.py`를 다시 실행한다.

## 5. LLM 판정

- **실행**: 데스크탑에 Ollama를 설치하고 `qwen3.5:4b`를 GPU에서 돌린다 [확정]. Ollama 프로그램은 항상 켜 두고(윈도우 시작 시 자동 실행), **모델은 요청 하나를 처리하는 동안만 올려 두었다가 요청이 끝나면 내린다** [확정]. 호출마다 `keep_alive=0`을 주면 매번 다시 로드되므로, 요청 안에서는 모델을 유지하고 마지막에 한 번만 내린다.
- **프롬프트는 고정한다.** 질문 한 줄만 바꿔도 판정이 바뀌는 것을 실측으로 확인했기 때문이다. 바꿀 때는 반드시 §11의 회귀 테스트를 다시 돌린다. 현재 프롬프트 원문은 detection-server 레포 `scripts/misinfo_lib.py`의 `PROMPT_TEMPLATE`이다(2026-10-01 개정, 아래 "추가 결정" 참고).
- **출력 형식 강제** [2026-10-01 개정]: Ollama의 구조화 출력(JSON 스키마)으로 1차 판정 `{core_claim, evidence_ids, reason, label}`을 **이 순서대로** 받는다. 모델은 앞에서부터 쓰므로 판정을 맨 뒤에 둬야 근거를 따진 다음 판정한다. `think:false`, `temperature:0`, `num_ctx:8192`(서버 기본값에 기대지 않고 명시).
- **판정 흐름** [2026-10-01 개정]: 재정렬 상위 5개는 한 문서에서 최대 2개까지만 고르고(다른 문서의 근거가 밀려나지 않게), 선택된 조각마다 같은 문서의 앞뒤 조각을 붙여 번호 매긴 근거 문단(합계 4,500자 이내)으로 넘긴다 → 1차 판정(LLM) → 반박이고 인용 문단이 있으면, 인용 문단을 문장 단위로 나눠 NLI 분류기(`klue/roberta-large`를 KLUE-NLI로 직접 학습, detection-server `scripts/train_nli.py`)로 1차가 정리한 핵심 주장과 모순인지 확인한다 → 모순 확률 0.8 이상인 문장이 든 문단만 `evidence`로, 1차 판정의 이유를 `reason`으로 내보낸다. 인용이 없거나 NLI가 확인하지 못한 반박은 내보내지 않는다. 반박의 정의는 "근거 문단이 사실이면 주장은 거짓일 수밖에 없다"이고, 속설을 소개만 하는 문단은 근거가 아니지만 "근거 없는 미신"이라고 평가하는 문단은 거짓 근거로 본다.
- **프롬프트 인젝션 대응**: 사용자 콘텐츠는 `[주장]` 칸 안에만 넣고 출력 형식을 스키마로 강제한다. 완전히 막을 수는 없다는 점을 인지하고 쓴다.
- **설정값으로 뺄 것** [확정]: 모델 이름, 근거 조각 수(기본 5), 이유 최대 길이, Ollama 주소와 타임아웃. 데스크탑에서 실측하며 조정한다.

## 6. 기존 기능 보호 — GPU 자원 큐 [확정, 2026-09-29 방향 변경]

**단순 잠금(mutex)이 아니라 작은 큐로 만든다.** 이유는 두 가지다. (1) 사용자가 영상 분석이 느려지는 걸 원하지 않아서, 잠그는 범위를 최대한 좁혀야 한다. (2) 이 프로젝트의 목적 중 하나가 "1인 사이드 프로젝트여도 대규모 트래픽에 대비하는 설계를 연습하는 것"([[project_veritae_deployment_traffic]]의 2026-09-29 동기 확인 참고) — 나중에 `project_veritae_deployment_traffic` 작업을 시작할 때 이 큐를 그대로 확장해서 쓸 수 있게 지금부터 큐 형태로 만든다.

- detection-server 안에 **GPU 자원 큐**를 둔다. GPU를 쓰는 작업(SPAI, dfdc, Whisper, e5, LLM)은 이 큐를 통해서만 실행되고, **한 번에 하나만** 실제로 돈다. 동시에 돌면 PyTorch 모델이 GPU 메모리 부족으로 실패하기 때문이다.
- **대기열에 상한을 둔다.** 너무 많이 쌓이면(설정값, 예: 10건) 새 요청은 큐에 넣지 않고 즉시 503으로 거절한다 — 타임아웃으로 조용히 죽는 대신 명확한 이유로 실패시키기 위함.
- **큐 길이와 대기시간을 로그로 남긴다.** 나중에 배포 트래픽 작업에서 지표(metric)로 승격하기 쉽게, 처음부터 구조화된 로그로 남긴다.
- **동시 실행 개수는 설정값(기본 1)으로 뺀다.** 지금은 GPU가 한 장이라 1이지만, 나중에 자원이 늘어나면 숫자만 바꾸면 되게 짠다.
- Ollama는 GPU 메모리가 모자라면 오류 없이 CPU와 RAM으로 넘어가 느려진다. 판정할 때마다 Ollama `/api/ps`로 GPU에 올라간 비율을 확인해 100%가 아니면 경고 로그를 남긴다.
- **잠금(큐 사용) 단위는 `subprocess.run()` 호출 하나, 또는 Ollama/임베딩 HTTP 호출 하나 단위다** — FastAPI 요청 전체를 큐에 넣지 않는다. 그래서:
  - 이미지: 사기감지가 CPU(EasyOCR)만 쓰므로 큐에 안 넣는다. SPAI만 큐를 탄다.
  - 음성: `scam_infer.py`(STT+Lilju, 사실상 Whisper 구간이 대부분) 호출 전체가 큐를 탄다. AntiDeepfake도 큐를 탄다(다만 §12에서 확인했듯 AntiDeepfake는 지금 CPU로 돌고 있어 실제로는 큐에 안 걸릴 수 있음 — 실측 필요).
  - 영상: dfdc 호출과 `scam_infer.py`(video 모드: STT+프레임 OCR+Lilju) 호출이 각각 큐를 탄다. **다만 `scam_infer.py` video 모드는 GPU를 쓰는 STT와 CPU만 쓰는 프레임 OCR이 한 프로세스 안에 섞여 있어서, 이 호출 전체를 큐에 넣으면 OCR 하는 동안에도 자리를 차지한다.** 완벽하게 쪼개려면 STT를 별도 서브프로세스 호출로 분리해야 하는데, 이번 스코프에서는 하지 않는다(범위 확대) — **아는 채로 남겨두는 절충**이다. 그래도 FastAPI 요청 전체를 잠그는 것보다는 훨씬 좁다.
  - misinfo_infer.py: SQLite 검색과 Kiwi 형태소 분석(CPU, 빠름) + e5 임베딩(GPU) + LLM 호출(GPU)이 섞여 있지만 CPU 부분이 짧아서 호출 전체를 큐에 넣어도 손해가 작다.

## 7. detection-server 변경 (veritae-detection-server)

- `scripts/scam_infer.py`: 결과 JSON에 `sentences`(분리된 문장 전체)를 추가한다. 기존 `score`/`evidence`는 그대로.
- `scripts/misinfo_infer.py` 신규: 문장 목록 JSON을 받아 §3의 1~4를 수행하고 `{wiki_snapshot, claims:[…]}`를 JSON으로 쓴다. 기존 모델들처럼 서브프로세스로 실행한다.
  - **실행 환경 [확정]:** 기존 `text-extraction` conda 환경(이미 torch·transformers 있음)에 kiwipiepy를 추가해 재사용한다. 새 환경을 만들지 않는다.
- `app/services/misinfo_runner.py` 신규: 서브프로세스 실행, 결과 파싱, 오류를 `MisinfoInferenceError`로 변환.
- `app/services/gpu_queue.py` 신규: §6의 GPU 자원 큐.
- `app/routers/image.py`, `audio.py`, `video.py`: 사기감지 결과의 `sentences`로 가짜정보 판정을 이어서 실행하고, 응답에 `misinformation_detection`을 추가한다. 문장이 하나도 없으면(텍스트 없음) null.
- `app/schemas.py`: `MisinformationDetectionResult`, `MisinformationClaim`, `WikiEvidence` 추가.
- `app/config.py`: §5의 설정값과 인덱스 파일 경로, `misinfo_infer.py` 경로와 타임아웃 추가.
- `scripts/build_wiki_index.py` 신규: §4 구축 스크립트.

## 8. Spring 변경 (veritae-server)

- `detection` 패키지: `MisinformationDetectionResult`, `MisinformationClaim`, `WikiEvidence` 레코드와 공용 파싱 클래스 `MisinformationDetectionJson`(ScamDetectionJson과 같은 방식). `ImageAnalysisResult` / `AudioAnalysisResult` / `VideoAnalysisResult`에 `misinformationDetection` 필드를 추가하고, HTTP 클라이언트 3곳이 `misinformation_detection`을 함께 파싱한다.
- `AnalysisRecord`: `misinfo_refuted_count`(Integer, nullable) 컬럼 추가 [확정: 리포트 집계용]. 기존 기록은 null(검사 안 함)로 두고 백필하지 않는다. `ddl-auto=update`라 별도 마이그레이션은 없다. `completedSync`, `markCompleted`, `markCompletedWithPartialError`가 이 값을 함께 받는다.
- `AnalysisRecordRepository`: 반박 개수가 1 이상인 완료 기록 수를 세는 메서드 추가.
- 리포트 응답에 `misinformationDetectedCount` 추가 [확정].
- `AnalysisApiMapper`, `AnalysisJobView`, `openapi.yaml`, API 명세서 PDF 스크립트(`scripts/generate_api_spec_pdf.py`) 갱신. Swagger 예시는 공유 스키마 예시 버그(`feedback_swagger_shared_schema_example_bug`) 때문에 명시 예시를 넣는다.
- **타임아웃 [확정]:** 지금은 임시로 넉넉한 값(제안: Spring `detection.read-timeout`을 300s→600s, detection-server `misinfo_infer` 타임아웃 300s)을 잡아두고, 데스크탑 실측 후 실제 걸리는 시간에 맞춰 조정한다. §6의 큐 대기시간까지 포함해서 잰다.

## 9. API 명세 [확정]

새 엔드포인트는 없다. 이미지·음성 응답, 영상 job 조회 응답, 기록 목록에 `misinformationDetection`을 `scamDetection` 옆에 추가한다.

```json
"misinformationDetection": {
  "model": "qwen3.5:4b",
  "wikiSnapshot": "2026-09-01",
  "claims": [
    {
      "sentence": "선풍기를 틀고 자면 사망한다.",
      "reason": "근거 문단은 선풍기 사망설을 과학적 근거가 없는 미신이라고 설명합니다.",
      "evidence": [
        {
          "title": "선풍기 사망설",
          "text": "선풍기 사망설이란, 밀폐된 방에서 얼굴을 향해 선풍기를 켜놓은 채로 잠을 자면 사망할 수 있다는 미신이다. …",
          "url": "https://ko.wikipedia.org/wiki/선풍기_사망설"
        }
      ]
    }
  ]
}
```

- **null**: 텍스트가 하나도 추출되지 않음(`scamDetection`과 같은 조건).
- **`claims`가 빈 배열**: 검사했지만 위키에서 반박되는 내용을 찾지 못함. **"모두 사실"이라는 뜻이 아니다.** 명세서 설명에 이 문장을 그대로 적는다.
- **점수 없음**: LLM은 보정된 확률을 주지 않는다.
- `evidence`는 판정에 쓴 근거 조각이다. `title`과 `url`은 위키백과 CC BY-SA 라이선스의 출처 표시 요건 때문에 필수이고, 앱 화면에도 "출처: 위키백과" 표기가 필요하다.
- 리포트 응답에 `misinformationDetectedCount`(반박된 주장이 1개 이상인 완료 기록 수)를 추가한다.

## 10. 오류 처리 [확정]

- 가짜정보 파이프라인이 고장 나면(Ollama가 응답하지 않음, 인덱스 파일을 못 읽음, 서브프로세스 실패, 타임아웃) **분석 요청 전체를 502로 실패시킨다.** 사기감지와 같은 규칙이다. 빈 결과가 "이상 없음"으로 오해되는 것을 막기 위해서다. 클라이언트에는 일반화된 메시지만 주고, 원인은 서버 로그에만 남긴다.
- **[확정]** 문장 하나의 LLM 출력이 형식에 맞지 않으면, 그 문장은 판단불가로 처리하고 경고 로그를 남긴다. 파이프라인 자체가 죽은 것(위 항목)과는 구분한다 — 문장 하나의 드문 형식 오류로 분석 전체를 실패시키지 않는다.

## 11. 테스트

- **단위 테스트(두 레포)**: 기존처럼 서브프로세스와 HTTP를 목(mock)으로 대신한다. 라우터가 `misinformation_detection`을 붙이는지, 오류 시 502를 내는지, 텍스트가 없으면 null인지, Spring이 파싱·저장·집계를 하는지 확인한다.
- **회귀 테스트셋 [확정]**: 오늘 만든 36건, 어려운 16건, 위키 검색 포함 20건을 detection-server 레포 `tests/regression/`에 넣고, 데스크탑에서 실행해 정확도·시간·GPU 메모리·큐 대기시간을 한 번에 재는 스크립트를 함께 둔다. 이 스크립트는 실제 모델을 쓰므로 일반 테스트(pytest)와 분리한다. 프롬프트나 설정값을 바꿀 때마다 이걸로 확인한다.

## 12. 자원과 남은 위험

- **GPU 메모리(8GB)**: GPU 잠금으로 한 번에 하나만 올라가므로 문제없다고 판단한다. 가장 큰 기존 작업은 Whisper large-v3(약 3~4GB), LLM은 약 4GB.
- **디스크**: 덤프, 변환 텍스트, 인덱스를 합쳐 약 10GB 이하로 예상한다. 구축 후 덤프와 중간 파일은 지울 수 있다. 데스크탑 여유 공간은 미확인.
- **RAM(16GB)**: 사용자 확인 결과 **지금도 분석 중에 꽉 찬다.** 원인은 CPU에서 도는 AntiDeepfake, EasyOCR, Lilju로 추정하지만 측정하지 않았다. 이번 추가분(Kiwi, SQLite 조회)은 1GB 이하로 예상하고, LLM과 e5는 GPU에서 돈다. RAM이 모자라면 실패하지 않고 느려진다. **이 위험을 알고 확정했다.** 구현 후 데스크탑 작업 관리자로 확인한다.
- **속도**: 데스크탑 GPU에서의 문장당 시간, 모델 로드 시간은 미측정이다. §5의 설정값(근거 조각 수, 모델 크기)으로 조정한다.

## 13. 결정 이력 (전부 확정됨, 2026-09-29)

애초 검토 필요 항목 A~F는 전부 사용자가 Claude 추천대로 확정했다("추천대로 진행하자", 2026-09-29). 그중 **B(GPU 잠금 단위)는 확정 과정에서 방향이 바뀌었다** — 처음 제안("사기감지 서브프로세스 전체를 잠가서 영상이 느려짐")을 사용자가 "느려지는 건 안 좋다"며 거부했고, 그 뒤 "1인 사이드 프로젝트여도 대규모 트래픽 대비를 연습하고 싶다"는 동기가 확인되면서 **§6처럼 서브프로세스/HTTP 호출 단위로 더 잘게 나누고, 단순 잠금이 아니라 대기열 상한·로그가 있는 작은 큐로 만드는 것으로 바뀌었다.** 나머지 A, C, D, E, F는 최초 제안 그대로 확정.

### 추가 결정 (구현·실측 후, 2026-09-30)

- **claims가 빈 배열/일부만 있을 때 화면 안내 문구 필요 [확정]**: 구현 완료 후 데스크탑에서 실측(19/20, 위험 오답 0건)까지 확인한 뒤, "거짓으로 판정된 문장만 보여준다"는 §1 원칙을 사용자가 재검토했다. 검토한 대안 셋: (A) 그대로 유지, (B) 지지/반박/판단불가를 전부 노출, (C) 반박만 보여주되 안내 문구 추가. B는 판단불가가 대부분(음성/영상 문장 상당수가 사실 검증 대상 자체가 아님)이라 실효가 작고, "참" 라벨이 반박보다 강한 주장이라 근거가 틀렸을 때 더 위험한 과신을 만들 수 있어 기각. C로 확정 — claims만 보여주고 판정 안 된 문장에 대해서는 침묵하는 대신, "표시 안 된 문장은 확인 안 됐을 수 있다"는 걸 화면에 명시한다(openapi.yaml `MisinformationDetectionResult` 설명 참고). 판단 근거: 이 기능의 목적이 사기·허위정보 예방이라, "거짓 확신(안 보이면 참이라고 오해)"이 "막연한 불확실성(안 보이면 모른다고 생각)"보다 훨씬 위험하다 - 후자로 치우치는 쪽을 택했다.

- **반박 판정을 근거 인용 기반으로 개정 [확정, 2026-10-01]**: 실제 이미지 분석(Swagger)에서 "선풍기를 틀고 자면 사망한다는 이야기를 들었어요"(OCR로 글자 일부 깨짐)가 반박으로 나왔는데, 이유 문장은 "근거와 일치합니다"로 반박이 아니라 지지하는 논리였고, 근거로는 검색 후보 5개가 전부 나가 속설의 가설만 담긴 조각과 무관한 문서(케니 맥코믹 등)까지 "반박 근거"로 표시됐다. 원인은 (1) 응답 형식이 label을 reason보다 먼저 쓰게 해서 판정을 먼저 정하고 이유를 끼워 맞춤, (2) 판정이 인용하지 않은 검색 후보까지 근거로 표시, (3) 약 200자 조각이 "가설이 있다"까지만 담고 뒤의 "근거 없다"를 잘라냄, (4) 20건 실측이 깔끔한 단정문의 라벨만 봐서 이런 입력과 근거 품질을 검증하지 못함. 사용자 지시("그 판단이 굉장히 중요하다", "부작용 없는 방식으로")에 따라, 맞는 판정까지 버리는 기계적 차단(인용 글자 대조, 한 문장만 보고 재확인, 두 판정 일치 요구)은 쓰지 않고 §5 판정 흐름처럼 개정했다. 처음에는 반박 후보를 생각 모드(`think:true`)로 재판정했으나, 데스크탑 진단에서 qwen3.5:4b가 생각에 컨텍스트 4096토큰을 전부 써서 JSON을 쓰기 전에 멈추고(`done_reason=length`) 매번 빈 응답을 냈다. 한도를 늘려도 재판정 1건에 수십 초가 걸려 분석 제한 시간 300초를 넘길 수 있어, 인용 문단만 따로 보고 확인하는 검증 단계로 바꿨다(사용자가 Claude 추천대로 확정). **전해 들은 말은 안의 내용으로 판정한다(사용자 결정)**. 반대로 "~라는 속설이 있다", "~는 잘못 알려진 것이다"처럼 속설을 속설이라고 소개하는 문장은 참인 문장이므로 문장 그대로 판정한다. 검증은 회귀 테스트셋에 이런 유형 14건을 추가하고, 반박마다 이유와 근거 원문을 사람이 직접 읽어 확인하며, 위험 오답 0건과 기존에 잡던 거짓 문장 유지를 통과 조건으로 한다.

- **반박 확인을 LLM 재검증에서 NLI 분류기로 교체 [확정, 2026-10-01]**: LLM(qwen3.5:4b)에게 인용 문단만 보여주고 다시 묻는 검증 단계는 데스크탑 실측 3회 동안 문구를 바꿀 때마다 오류가 다른 문장으로 옮겨 다녔고(맞게 잡던 "세종대왕은 고려의 왕", "태양은 지구 주위를 돈다"를 다음 실측에서 거꾸로 추론해 버림), 마지막 실측에서는 "인간이 뇌의 10퍼센트만 사용한다는 것은 근거 없는 속설이다"(참인 문장)를 거짓으로 표시하는 위험 오답까지 냈다. 더 큰 LLM(9b, 6.6GB)은 8GB GPU를 다른 탐지 모델과 나눠 써야 해서 제외했다. 대신 판단 방식이 다른 NLI 분류기로 확인하기로 했다(사용자가 Claude 추천대로 확정). 노트북에서 실제 위키 문단으로 NLI 모델 4종을 비교한 결과, KLUE-NLI로 학습한 `klue/roberta-large`만 진짜 반박 문장(0.81~0.999)과 아닌 문장(대부분 0.05 미만)을 구분했고, 다른 모델(xlm-roberta-large-xnli, mDeBERTa, klue-roberta-base)은 무관한 문장에 높은 모순 점수를 주거나 엉뚱한 근거 문장을 골랐다. 그 공개 모델은 라이선스 표기가 없어 같은 방법으로 직접 학습한다(원재료 KLUE 데이터셋·KLUE-RoBERTa 모두 CC BY-SA 4.0). NLI도 혼자서는 참인 문장에 오판하는 경우가 있어("세종대왕은 조선의 왕이다" vs 같은 동음이의 문단의 "중국 세종은 상나라 왕의 묘호") LLM 1차 판정과 둘 다 반박이라고 할 때만 표시한다. 남은 위험: 1차 판정이 "~는 근거 없는 속설이다" 같은 참인 문장을 속 내용으로 잘못 정리하면 NLI도 반박으로 확인한다. 실측 8회 모두 제대로 정리했고, 회귀 테스트셋에 이 유형이 들어 있어 발생하면 위험 오답으로 드러난다.

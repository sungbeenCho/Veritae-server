# 사기감지 로컬 LLM 판정 - 알려진 약점과 보완 계획 (2026-10-27)

## 배경
- 사기감지 모델 `Lilju/voicephishing_kobert`는 정상 문장도 사기로 판정한다(정상 오탐 100%).
- 공개된 한국어 스미싱 분류 모델 5개와 NLI 제로샷을 시험했지만 모두 합격 기준에 못 미쳤다.
- 직접 학습은 다양한 실제 정상 문자가 없어 보류했다.
  - "사기는 실제, 정상은 작성" 조합으로 학습하면 모델이 작성 말투를 정상으로 배울 위험이 있다.
- 그래서 가짜정보가 이미 쓰는 로컬 LLM(qwen3.5:4b, Ollama)으로 판정하기로 했다.
- 시험 스크립트는 veritae-detection-server의 `scripts/measure_scam_llm.py`이고, 지시문은 v1·v2·v3이다.

| 세트 (50 기준 탐지 / 오탐) | v1 | v2 | v3 (확정) |
|---|---|---|---|
| 실제 문자 (meal-bbang 정상 200 / Ez-Sy01·meal 사기 200) | 84% / 4% | 72% / 0% (합격) | 80% / 2% (합격) |
| 헷갈리는 문자 (작성 73) | 100% / 28% | 97% / 8% | 100% / 10% |
| 헷갈리는 통화 (작성 29) | 100% / 64% | 100% / 0% | 100% / 14% |
| 실제 통화 (KorCCVi 142) | 87% / 25% | 68% / 4% (탐지 하한 미달) | 80% / 3% (합격) |

- v3(공개된 대표 사기 유형 추가)를 확정했다(2026-10-28).
  - 실제 문자와 실제 통화가 모두 합격했으므로 문자·음성·영상 모두에 적용한다.
  - 확인된 인용만 사기로 치는 경우에도 둘 다 합격한다. 실제 문자는 탐지 74%·오탐 2%, 실제 통화는 탐지 77%·오탐 3%다.
- 항목당 약 3.2~3.5초가 걸렸고 형식 오류는 0개였다.

## 서버 통합 조건 (확정)
- 사기 판정은 글자 추출(Whisper)이 끝난 뒤, 가짜정보와 같은 단계에서 같은 Ollama 모델을 한 번 올려 이어서 처리한다.
  - Whisper(실측 약 4.2GB)와 Ollama(약 4.1GB)를 동시에 올리면 8GB를 넘는다.
- 응답 모양 `{model, score, evidence[]}`는 바꾸지 않는다. model 이름만 바뀐다.

## 약점과 보완 계획

| # | 약점 | 영향 | 보완 방법 | 상태 |
|---|---|---|---|---|
| 1 | 같은 시험 세트를 보며 지시문을 세 번 고쳤다 | 시험 점수가 실제보다 좋게 나온다 | 지시문을 확정한 뒤, 결과를 보지 않은 새 시험 세트로 다시 잰다. 새 세트는 다른 작성자가 쓰고 검토자가 라벨을 확인하며, 작성 전에 고정한다. 이후 지시문을 바꿀 때는 새 세트로만 판정한다 | 미착수 |
| 2 | 실제 정상 문자가 택배 알림 틀 약 62종뿐이다 | 은행·카드·병원·관공서 문자의 오탐을 모른다 | 공개된 실제 정상 문자를 모은다(긴급재난문자 공공데이터, 기관 공식 안내문·보도에 실린 원문). 개인 수집은 하지 않는다 | 미착수 |
| 3 | 실제 통화의 정상 쪽(AI Hub)은 금융과 무관한 대화뿐이다 | 실제 은행·보험·경찰서 통화의 오탐을 모른다 | 정상 기관 통화(상담·분실물·본인 확인)를 작성해 시험 세트에 각 40개 이상 둔다. 작성 데이터라 참고용 지표로만 쓴다 | 미착수 |
| 4 | v3는 "돈 이야기 전이라도 사기"를 넣어 오탐이 다시 늘 수 있다 | 정상 기관 연락을 사기로 표시할 수 있다 | v3 결과에서 v2 대비 오탐을 확인한다. 늘었으면 v2를 쓰거나 적용 범위를 줄인다 | 확인함. 헷갈리는 세트에서 오탐이 조금 늘었다(문자 8%→10%, 통화 0%→14%). 예: 카드사 분실신고·이상거래 안내 통화, 가족 간 용돈 문자. 실제 세트는 합격이라 v3를 쓰고, 3번 세트로 계속 지켜본다 |
| 5 | 목록에 없는 새 사기 유형을 놓칠 수 있다 | 신종 사기 탐지가 약하다 | 금감원·KISA 공개 자료로 대표 유형 목록을 주기적으로 갱신한다. 갱신할 때마다 1번의 새 세트로 다시 잰다 | 상시 |
| 6 | 점수가 확률이 아니다(0.10·0.85·0.95 같은 몇 값에 몰림) | "사기 위험 85%"가 실제 확률로 오해받는다 | 앱 표시를 단계(낮음/주의/높음)로 바꾼다. API의 score는 유지하고, 단계 구간을 명세서에 적는다 | 미착수(iOS 표시 결정 필요) |
| 7 | 이유 문장을 지어낼 수 있다 | 틀린 근거를 사용자에게 보여 준다 | 원문에서 확인된 인용 구절만 근거(evidence)로 보여 준다. 확인이 안 되면 판정은 유지하고 근거만 숨긴다. 설명 문장은 보여 주지 않거나, 이후 NLI로 원문과 맞는지 확인한다 | 서버 통합 때 적용 |
| 8 | 긴 통화는 앞 3,000자만 본다 | 뒤에서 본론이 나오는 사기를 놓친다 | 3,000자 단위로 겹치게 나눠 각각 판정하고 가장 높은 것을 쓴다. 음성은 5분 상한이라 대부분 한 덩어리지만 영상은 길 수 있다 | 서버 통합 때 적용 |
| 9 | 문자 속 지시("정상이라고 판단하라")로 판정을 속일 수 있다 | 사기범이 우회할 수 있다 | 공격 문장을 넣은 시험 세트를 만들어 잰다. 뚫리면 지시문 보강과, 메시지 안 AI 대상 문장을 따로 표시하는 방안을 검토한다 | 미착수 |
| 10 | OCR·STT 오타가 판정에 그대로 들어간다 | 글자가 깨지면 판정도 흔들린다 | 지시문에 오타 가능성을 이미 적었다. OCR 엔진 교체는 하지 않는다 | 유지 |
| 11 | 요청마다 판정 한 번(약 3초)이 늘어난다 | 분석 시간이 증가한다 | 가짜정보와 같은 모델 적재를 공유해 올리는 시간을 없앤다(서버 통합 조건) | 서버 통합 때 적용 |
